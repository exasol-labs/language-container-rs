# Feature: cargo-exaudf

Provides the `cargo exaudf` developer CLI that scaffolds a Rust UDF crate, builds it into a fully-static musl `.so`, and validates that a built `.so` is ABI-compatible with the current SDK — so authors never hand-manage the musl target triple or ABI constants.

## Background

<!-- DELTA:CHANGED -->
`cargo-exaudf` is a Cargo subcommand binary invoked as `cargo exaudf <subcommand>`. By default `build` targets `<host-arch>-unknown-linux-musl`, derived from the host architecture (`x86_64` or `aarch64`) rather than hardcoded; an optional `--target <triple>` flag overrides the triple for a native build on that host (cross-compilation is out of scope). The author never hand-manages the triple for the common case. The CLI performs no network I/O. ABI compatibility is judged against the same `EXA_UDF_ABI_VERSION` and `EXA_SDK_FINGERPRINT` constants baked into `exasol-udf-sdk`. The scaffold generated by `new` models the scalar RETURNS value-return channel.
<!-- /DELTA:CHANGED -->

## Scenarios

<!-- DELTA:CHANGED -->
### Scenario: build produces a fully-static musl .so

* *GIVEN* a UDF crate produced by `cargo exaudf new` on a host of architecture `<host-arch>` (`x86_64` or `aarch64`)
* *WHEN* the author runs `cargo exaudf build`
* *THEN* the CLI MUST invoke `cargo build --release --target <host-arch>-unknown-linux-musl`, deriving `<host-arch>` from the host rather than hardcoding `x86_64`
* *AND* it MUST print the path `target/<host-arch>-unknown-linux-musl/release/lib<crate>.so`
<!-- /DELTA:CHANGED -->

<!-- DELTA:CHANGED -->
### Scenario: build installs the musl target when missing

* *GIVEN* a host where the selected `<host-arch>-unknown-linux-musl` target is not installed
* *WHEN* the author runs `cargo exaudf build`
* *THEN* the CLI MUST run `rustup target add <host-arch>-unknown-linux-musl` for the selected triple before building
* *AND* it MUST proceed with the build once the target is present
<!-- /DELTA:CHANGED -->

<!-- DELTA:NEW -->
### Scenario: build honors an explicit target override

* *GIVEN* a UDF crate and an author on a host whose architecture matches `<triple>`
* *WHEN* the author runs `cargo exaudf build --target <triple>` (e.g. `--target aarch64-unknown-linux-musl`)
* *THEN* the CLI MUST build for `<triple>` instead of the host default, installing it via `rustup target add <triple>` if missing
* *AND* it MUST print the path `target/<triple>/release/lib<crate>.so`
* *AND* it MUST NOT attempt to provision a cross-compilation toolchain, since only native builds for the host architecture are supported
<!-- /DELTA:NEW -->
