# Feature: cargo-exaudf

<!-- DELTA:CHANGED -->
Provides the `cargo exaudf` developer CLI that scaffolds a Rust UDF crate, builds it into a glibc-dynamic cdylib `.so`, and validates that a built `.so` is ABI-compatible with the current SDK — so authors never hand-manage the build target or ABI constants.
<!-- /DELTA:CHANGED -->

## Background

<!-- DELTA:CHANGED -->
`cargo-exaudf` is a Cargo subcommand binary invoked as `cargo exaudf <subcommand>`. By default `build` runs a plain host `cargo build --release`, producing a glibc-dynamic cdylib at `target/release/lib<crate>.so`; an optional `--target <triple>` flag overrides the build target for a native build on that host. The CLI performs no network I/O. ABI compatibility is judged against the same `EXA_UDF_ABI_VERSION` and `EXA_SDK_FINGERPRINT` constants baked into `exasol-udf-sdk`. The scaffold generated by `new` models the scalar RETURNS value-return channel.
<!-- /DELTA:CHANGED -->

## Scenarios

<!-- DELTA:CHANGED -->
### Scenario: new scaffolds a buildable UDF crate

* *GIVEN* a target directory that does not yet contain a crate
* *WHEN* the author runs `cargo exaudf new my-udf`
* *THEN* the CLI MUST create a `Cargo.toml` with `crate-type = ["cdylib"]` and dependencies on `exasol-udf-sdk` and `exasol-udf-macros` whose version pins track the current SDK major.minor line
* *AND* it MUST create a `src/lib.rs` containing a `#[exasol_udf]` entry point that models the scalar RETURNS channel, returning `Result<Option<i64>, UdfError>` with a placeholder `Ok(None)` body
* *AND* the generated crate MUST compile as written against that SDK, the macro deriving the RETURNS output shape from the `Option<i64>` return type
<!-- /DELTA:CHANGED -->

<!-- DELTA:REMOVED -->
### Scenario: build produces a fully-static musl .so

* *GIVEN* a UDF crate produced by `cargo exaudf new`
* *WHEN* the author runs `cargo exaudf build`
* *THEN* the CLI MUST invoke `cargo build --release --target x86_64-unknown-linux-musl`
* *AND* it MUST print the path `target/x86_64-unknown-linux-musl/release/lib<crate>.so`
<!-- /DELTA:REMOVED -->

<!-- DELTA:REMOVED -->
### Scenario: build installs the musl target when missing

* *GIVEN* a host where the `x86_64-unknown-linux-musl` target is not installed
* *WHEN* the author runs `cargo exaudf build`
* *THEN* the CLI MUST run `rustup target add x86_64-unknown-linux-musl` before building
* *AND* it MUST proceed with the build once the target is present
<!-- /DELTA:REMOVED -->

<!-- DELTA:NEW -->
### Scenario: build produces a loadable host cdylib

* *GIVEN* a UDF crate produced by `cargo exaudf new`
* *WHEN* the author runs `cargo exaudf build` with no `--target` flag
* *THEN* the CLI MUST invoke `cargo build --release` for the host target, passing no `--target`
* *AND* it MUST print the path `target/release/lib<crate>.so`
* *AND* the produced `.so` MUST be a cdylib that exports at least one `__exa_udf_entry_<NAME>` symbol
<!-- /DELTA:NEW -->

<!-- DELTA:NEW -->
### Scenario: build honors an explicit target override

* *GIVEN* a UDF crate and a host whose toolchain has the target triple `<triple>` installed
* *WHEN* the author runs `cargo exaudf build --target <triple>`
* *THEN* the CLI MUST invoke `cargo build --release --target <triple>`
* *AND* it MUST print the path `target/<triple>/release/lib<crate>.so`
<!-- /DELTA:NEW -->

<!-- DELTA:CHANGED -->
### Scenario: build verifies the artifact exports at least one named entry point

* *GIVEN* an author crate annotated with `#[exasol_udf]`
* *WHEN* the author runs `cargo exaudf build`
* *THEN* after producing the `.so` the CLI MUST verify the artifact exports at least one `__exa_udf_entry_<NAME>` symbol resolving to a non-null vtable
* *AND* a build whose artifact exports no named entry point MUST fail with a clear error rather than producing a silently-unusable `.so`
<!-- /DELTA:CHANGED -->
